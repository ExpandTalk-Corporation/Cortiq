# Transfer Impact Assessments (draft) — CortIQ, 2026-10-14

**Status: draft for review by counsel. Not legal advice.** Prepared by Expandtalk Corporation AB (CortIQ) as processor, under Art. 46 GDPR and EDPB Recommendations 01/2020. One assessment per US sub-processor listed in DPA §6.1.

Before relying on these, confirm: (1) CortIQ has accepted each provider's DPA; (2) the provider's DPF status on dataprivacyframework.gov on the date of review.

---

## 1. Supabase, Inc. (database, auth, server functions)

| Item | Assessment |
|---|---|
| Data | All CortIQ processing: page views, sessions, consent records, AI-bot hits, conversion events, hashed emails (SHA-256), account data. IPs truncated before storage; bot IPs nulled after 30 days. |
| Data subjects | Visitors of Customers' websites; Customers' account users. |
| Location | AWS eu-north-1 (Stockholm). Transfer arises only through remote access by Supabase or its sub-processors from outside the EEA (support, operations). |
| Transfer tool | SCCs Module 3 in the Supabase DPA (Decision 2021/914). Supabase's DPA does not rely on the EU-US DPF. |
| Third-country law | US: FISA §702 and EO 12333 can reach electronic communication service providers. EO 14086 and the Data Protection Review Court apply to US intelligence access regardless of DPF certification. |
| Practical likelihood | Low. Data is pseudonymous web analytics with truncated IPs and no direct identifiers; it is of no evident intelligence interest. Supabase publishes no history of government requests for EU customer data (verify its transparency report). |
| Supplementary measures | Storage in the EU; encryption in transit (TLS) and at rest (AWS); IP truncation and short IP retention; hashed emails only; RLS company isolation; least-privilege service-role use in server functions. |
| Conclusion | Transfer may proceed under SCCs with the measures above. Re-assess yearly or if Supabase changes region, DPA or sub-processors. |

## 2. Plus Five Five, Inc. (Resend) — email delivery of exports

| Item | Assessment |
|---|---|
| Data | For exports over 10,000 rows only: the recipient's email address and a signed download link to the export in CortIQ's EU storage (valid one hour). The export file itself is not sent to Resend. |
| Location | USA. |
| Transfer tool | EU-US DPF (adequacy decision 2023/1795, Art. 45) — confirm listing; SCCs Module 3 in the Resend DPA as fallback. |
| Practical likelihood | Low; occasional, Customer-initiated messages. |
| Supplementary measures | Sent only on explicit Customer action; the link expires after one hour; smaller exports are downloaded in the browser and never reach Resend. |
| Conclusion | Transfer may proceed under DPF (primary) and SCCs. |

## 3. Anthropic, PBC — AI insights (CortIQ's own key)

| Item | Assessment |
|---|---|
| Data | Aggregated statistics per site. Overview insights: page paths without query strings, page-view and session counts, device breakdown, form names and conversion rates. KPI insights: monthly KPI figures and traffic-channel totals. No visitor identifiers, IPs or emails. |
| Location | USA. |
| Transfer tool | SCCs Module 3 in Anthropic's Data Processing Addendum (confirm DPF status separately). |
| Residual personal data | Page paths can in rare cases contain personal data (e.g. `/users/jane-doe`). Query strings are already removed. |
| Supplementary measures | Aggregation; path-only URLs; no identifiers; prompts instruct the model to treat data as untrusted. Consider stripping path segments that look like emails or long numeric IDs before sending. |
| Conclusion | Low risk; transfer may proceed under SCCs. |

## 4. Cloudflare, Inc. — geo edge Worker and optional Cloudflare integration

Added 2026-11-18 (legal review `docs/legal/2026-11-geo-worker-review.md`, proposal (c)). Also closes the gap that Cloudflare has been in DPA §6.1 since 1.4 without a TIA.

| Item | Assessment |
|---|---|
| Data | Geo edge: every request from the tracking script, aggregate script and consent banner, in transit – full IP address, user agent, request body and headers. The Worker derives country and US/CA region and forwards them in a signed header (valid 60 s) to Supabase (EU). No storage in the Worker; Workers Logs disabled (`[observability] enabled = false`, checked in the dashboard on [DATE]). Upstream `Set-Cookie` is dropped (PR #162); checked 2026-11-18 that GET `/geo-check` and POST `/track-event` via the Worker return no `Set-Cookie`. Optional integration: as in DPA §6.1. |
| Data subjects | Visitors to Customers' websites, before and after consent. |
| Location | Cloudflare's global edge; normally the data centre nearest the visitor. No regional restriction on the free plan. |
| Transfer tool | SCCs Module 3 in Cloudflare DPA v6.4 (incorporated in the Self-Serve Subscription Agreement of 12 Sept 2025); UK Addendum for UK data. Cloudflare also participates in the EU-US DPF (listing checked on dataprivacyframework.gov on [DATE]). Contracting party: Expandtalk Corporation AB (account details and DPA acceptance recorded on [DATE]). |
| Third-country law | US: FISA §702 and EO 12333 can reach Cloudflare as a provider of electronic communication services. EO 14086 and the Data Protection Review Court apply. |
| Practical likelihood | Low. Transit only, no storage by CortIQ at Cloudflare; data is ordinary web-request metadata. Cloudflare DPA §8 commits to notifying the customer of third-party requests unless prohibited. Check Cloudflare's transparency report yearly. |
| Residual risk | Cloudflare may use "Network Data" derived from traffic to provide and improve its services (Self-Serve Subscription Agreement §2.5.5), and may add cookies in security challenges (§2.5.3). Responses from the Worker are checked for `Set-Cookie`. If the Worker fails (and for script versions before the Worker release), requests go directly to Supabase, whose own Cloudflare zone answers with a `__cf_bm` bot-management cookie (HttpOnly, Partitioned, 30 minutes). Browsers store it only for credentialed requests (navigator.sendBeacon in the tracker up to 5.5.15, after analytics consent); the aggregate script (credentials: 'omit'), the banner's fetch calls and every tracker request from 5.5.16 (credentials: 'omit', no sendBeacon) do not store it. This is a device-storage (ePrivacy) point, not a transfer point; see the privacy policy, section 6. |
| Supplementary measures | TLS end to end; no Worker storage or logging; signed, short-lived token; raw IP never stored by CortIQ; fallback to direct EU path if the Worker fails. |
| Conclusion | Transfer may proceed under SCCs, with DPF as an additional basis. Re-assess yearly, on a change of Cloudflare DPA version, or on a CJEU ruling in C-703/25 P. |
